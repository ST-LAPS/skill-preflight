# فحص المهارات — Skill Preflight

أداة من ST-LAPS تكشف بعض مشكلات حزم مهارات الوكلاء قبل نشرها: الروابط المحلية المفقودة، ومتطلبات التشغيل غير المذكورة، وافتراضات أوامر Unix التي تحتاج مراجعة عند دعم Windows.

**الإصدار 0.3.1 معاينة تجريبية مجانية بترخيص MIT.** تتوفر كأداة محلية وGitHub Action. ليست خدمة مدفوعة ولم تُنشر في npm.

## التشغيل

تحتاج Node.js 20 أو أحدث، وGit لتنزيل المستودع. لا توجد حزم npm إضافية، ولا تحتاج مفتاح API.

```sh
git clone https://github.com/ST-LAPS/skill-preflight.git
cd skill-preflight
node cli.mjs examples/ready --lang ar
node cli.mjs examples/broken --lang ar --format markdown
node --test
```

المثال الأول سليم. المثال الثاني يحتوي أخطاء متعمدة وينتهي برمز خروج 1.

## فحص ملفاتك

```sh
node cli.mjs ./skills --lang ar
node cli.mjs ./skills --lang ar --format json --output report.json
node cli.mjs ./skills --lang ar --strict
node cli.mjs --help --lang ar
```

استبدل `./skills` بمجلد المهارات لديك أو بمسار ملف `SKILL.md`. ضع مسار Windows بين علامتي اقتباس إذا احتوى مسافات. لا حاجة إلى رفع الملفات إلى أي خادم.

## دعم العربية

- تقارير نصية وMarkdown وJSON بالعربية، والإنجليزية هي اللغة الافتراضية (`--lang en`).
- قراءة النصوص العربية وأسماء الملفات العربية والروابط المرمزة.
- التعرف على عناوين «المتطلبات» و«متطلبات التشغيل» و«المتطلبات الأساسية» و«الاعتماديات» و«التبعيات»، بما فيها العناوين المشكولة.
- اكتب أسماء بيئات التشغيل بصيغتها الأصلية مثل `Python` و`Node.js` داخل قسم المتطلبات.
- تبقى مفاتيح JSON ورموز القواعد وقيم severity بالإنجليزية لضمان ثبات التكاملات.
- تحتاج شاشة الأوامر إلى دعم UTF-8 وخط عربي. تفاصيل أخطاء نظام الملفات قد تبقى بلغة النظام.

مثال قسم متطلبات صحيح:

````markdown
## متطلبات التشغيل
Node.js 20 أو أحدث.

```sh
node --version
```
````

## استخدامها داخل GitHub

أضف الخطوتين إلى ملف Workflow في مستودعك بعد تحديد حدث التشغيل والصلاحيات المناسبة:

```yaml
steps:
  - uses: actions/checkout@v7
  - uses: ST-LAPS/skill-preflight@v0.3.1
    id: preflight
    with:
      path: ./skills
      language: ar
      strict: 'false'
```

استبدل `./skills` بمجلد المهارات. ستجد التقرير في ملخص التشغيل، والأعداد في مخرجات الخطوة `skills` و`errors` و`warnings`. لا تحتاج إلى مفتاح API أو تثبيت Node.js في خطوة مستقلة. يتطلب الإجراء بيئة Runner تدعم Node.js 24، ويبقى مسار الفحص داخل `GITHUB_WORKSPACE`. استخدم صلاحية `contents: read`، وثبّت الإجراءات على معرّفات commits راجعتها عند الاستخدام الإنتاجي.

## جرّب الأداة على مهاراتك

إذا كنت تدير مستودع مهارات، افحصه محليًا أو باستخدام GitHub Action. أخبرنا بما ساعدك على إجراء تعديل، أو بالخطوة التي تعطل عندها الإعداد، أو بالتحذير الذي احتاج إلى توضيح. إذا أعدت الفحص بعد التغيير التالي لمهاراتك، أضف النتيجة إلى البلاغ نفسه. البلاغ علني، لذا شارك ملخصًا خاليًا من البيانات الحساسة.

[شارك ملاحظات التجربة](https://github.com/ST-LAPS/skill-preflight/issues/new?template=pilot-feedback.md)

## رموز الخروج

| رمز الخروج | المعنى |
|---|---|
| 0 | لا توجد أخطاء؛ التحذيرات مسموحة افتراضيًا |
| 1 | توجد أخطاء، أو تحذيرات عند تفعيل `--strict` |
| 2 | خطأ في الخيارات أو قراءة الملفات أو كتابة التقرير |

## الحدود

تُحل الروابط التي تبدأ بـ`{baseDir}/` نسبةً إلى مجلد ملف المهارة، وتبقى خاضعة لحدود الفحص. الروابط ذات المتغيرات الأخرى أو أمثلة `URL` تظهر كتحذير للمراجعة بدل اعتبارها ملفات مفقودة. تُقبل الأوصاف متعددة الأسطر في YAML. التحذيرات ليست أخطاء مؤكدة: قد تكون المتطلبات مذكورة في موضع آخر أو تكون أوامر Unix مقصودة في مهارة تدعم Linux فقط.

الفحص ثابت؛ لا تُنفّذ التعليمات أو السكربتات، ولا تُرسل الملفات، ولا يُستخدم نموذج ذكاء اصطناعي. لا تقيّم الأداة جودة النص العربي أو الإنجليزي، ولا تتحقق من سلوك المهارة عند تشغيلها. تدعم جزءًا محدودًا من YAML وروابط Markdown المباشرة؛ لا تفحص الروابط الخارجية أو الروابط المرجعية أو عناوين المقاطع. النتيجة النظيفة ليست ضمانًا أمنيًا أو ضمان توافق.

إذا كانت المهارات تشترك في ملفات بمجلدات أعلى، افحص جذر المستودع حتى تكون الملفات المشتركة داخل حدود الفحص. الروابط الخارجة عن هذه الحدود تُصدر تحذيرًا ولا تُتبع.

أرسل مثالًا صغيرًا بلا بيانات حساسة عبر [Issues](https://github.com/ST-LAPS/skill-preflight/issues) مع النتيجة المتوقعة. راجع [الدليل الإنجليزي](README.md) للقواعد وطريقة الاستخدام مع GitHub Actions.
